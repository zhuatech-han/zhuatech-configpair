## 本地运行

需要Docker及Docker Compose2、Python3。源码开发为Java21／Maven3.9、Node24.19.0／npm11。Java／Maven可直接使用官方`maven:3.9-eclipse-temurin-21`，无需宿主安装。

```bash
python3 scripts/init-env.py
docker compose config --quiet
docker compose up --build -d --wait
```

首次脚本以0600创建忽略的.env，独立随机生成数据库、root和管理员口令，不覆盖已有配置。打开`http://127.0.0.1:8133/`，账号admin，口令在本机.env的ADMIN_PASSWORD；只在空库初始化。建立真实部门和岗位后开始使用，没有固定演示账号或虚构业务。

| 变量 | 用途 |
|---|---|
| DATABASE_PASSWORD／MYSQL_ROOT_PASSWORD／ADMIN_PASSWORD | 必填，本机随机；不可纳入Git |
| WEB_PORT／BIND_ADDRESS | 默认8133／127.0.0.1；仅前端映射端口 |
| COOKIE_SECURE | 本地HTTP false，对外可信HTTPS设true |
| DATABASE_URL／DATABASE_USER／DATABASE_CATALOG | 后端支持外部数据库连接；默认Compose内网库zhuatech_configpair／账号configpair。外部连接需通过部署覆盖文件的backend.environment传入，仅写入.env不会自动注入这三项；覆盖需配置一致且单独审核 |

Compose中数据库不暴露宿主端口。健康入口`/actuator/health`，后台只公开health端点。账号会话30分钟，BCrypt12轮、CSRF、登录限流与即时撤权。对外部署须配置可信HTTPS、受限数据库账号、可靠备份、访问控制与代理转发头过滤；本版不提供多租户、外部证据签名或高可用。

## 数据库与升级

Flyway`V1__identity.sql`创建身份与管理目录，`V2__pair_coverage.sql`创建组合测试领域、幂等和历史表。Hibernate只验证结构，不自动建表改表。升级新增版本迁移，先在独立测试库验证；不要编辑已发布SQL、禁用校验或自动repair历史。

## 受限备份

备份可能包含账号散列、参数模型和证据参考，必须限制访问、加密存储并验证恢复。先用umask限制新文件权限：

```bash
mkdir -p private-backups
umask 077
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump -uroot --single-transaction --routines --events --no-tablespaces zhuatech_configpair' > private-backups/configpair.sql
```

恢复演练使用不同Compose项目名、独立全新数据库卷和其他回环端口。复用已验证应用镜像，不把演练指向原数据库。先只启动恢复项目mysql，导入受限备份，再启动应用；避免空库初始化与导入并发。使用相同初始化配置与实际备份账号验证；不要把.env复制到公开目录。

```bash
# 对自行核对过的独立恢复项目执行，数据库连接保持在该项目内网
docker compose -p configpair-restore -f compose.yaml -f private-backups/restore.override.yaml up -d --wait mysql
docker compose -p configpair-restore -f compose.yaml -f private-backups/restore.override.yaml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot zhuatech_configpair' < private-backups/configpair.sql
docker compose -p configpair-restore -f compose.yaml -f private-backups/restore.override.yaml up -d --wait
TEST_URL=http://127.0.0.1:18133 python3 scripts/smoke.py --verify
```

覆盖文件应把frontend端口设为独立18133并引用实际已验证backend／frontend镜像。恢复脚本比对所有捕获响应、随机测试账号和幂等响应；仅用于明确可丢弃的隔离验收实例。

## 验收与资源

```bash
python3 scripts/smoke.py --allow-test-writes
python3 scripts/smoke.py --capture
# 重启同一测试项目后
python3 scripts/smoke.py --verify
```

`--allow-test-writes`写入带TEST标记的隔离验收数据，禁止对实际使用实例执行。`output/qa-state.json`包含随机测试口令和比较快照，0600且忽略；不要公开日志或备份。执行失败先读受限日志修复，不跳过测试或清空原库。清理仅明确本次测试项目的容器、网络和数据库卷，不停止其他项目或删除业务卷。
