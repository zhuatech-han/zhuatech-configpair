# ConfigPair 架构与数据

知华科技（上海如静知华信息科技有限公司） · <https://www.zhuatech.cn/> · 商业咨询微信 zhuatech / zhuatech2。

## 系统边界

Vue3响应式管理／执行界面 → Nginx同源转发 → Java21 Spring Boot4.0.7 WebMVC／Security／JPA → MySQL8.4。Flyway版本化建表，Hibernate只验证结构。服务端以UTC微秒保存业务时间，页面按Asia/Shanghai显示。

核心不调用外部模型或测试平台。参数、准则和结果由人员明确输入；算法生成测试配置，不访问被测系统。对象、环境和构建标识用于记录，不能证明测试环境与文字声明相同。

## 主要数据

| 表 | 内容 |
|---|---|
| pair_job | 唯一编号、部门、对象、构建／环境／准则、指定岗位、状态、手工版本和各级摘要 |
| pair_factor | 参数编码、名称、候选值JSON；同计划编码唯一 |
| pair_constraint | 同计划两个不同参数的明确禁配；规范左右次序避免反向重复 |
| pair_revision | 不可变输入及生成计划JSON、算法版本、输入和计划SHA-256 |
| pair_editor | 所有历史设计人；不能通过角色变化成为独立复核或执行人 |
| pair_result | 活动生成版本每例的人工PASS／FAIL／BLOCKED、现象、证据参考、人员和时间 |
| command_record | UUID请求键、人员及完整操作内容指纹、稳定响应 |
| business_event | 状态／摘要历史；结果修订前后完整事实快照 |
| 身份目录及audit_event | 账号、角色权限、部门、菜单、字典、参数和操作审计 |

复合外键使禁配参数与结果生成版本始终属于同一父计划。活动版本也通过复合外键关联父计划。报告和历史 JSON 不依赖被删除的草稿参数实体。业务数据、随机口令及备份不纳入源码。

## FEASIBLE-PAIR-GREEDY-1

1. 校验2至8个参数、每个2至8个候选值、原始组合不超过20000及禁配不超过80条。
2. 按参数和值的稳定顺序枚举完整合法配置，在后一个参数已赋值时剪去违反二元禁配的分支。
3. 汇总合法配置中出现的所有两两值对，形成真正可达的覆盖宇宙；单独列出不可达候选值和排除值对数量。
4. 每次选择新增未覆盖值对最多的合法配置；同分选择最早的配置。保留完整参数赋值和可达值对索引，直到全部覆盖，最多256例；超限明确失败。
5. 执行覆盖取当前PASS／FAIL用例的值对并集，通过覆盖只取PASS。阻塞不视为执行；不同口径重叠不能简单相加。

算法是自主有界枚举和贪心实现，没有复制或集成ACTS。概念参考[NIST组合测试教程](https://csrc.nist.gov/pubs/sp/800/142/final)及[使用边界](https://csrc.nist.gov/Projects/automated-combinatorial-testing-for-software/software-testing-methodology/dos-and-don-ts-of-testing)。只证明模型下的二元覆盖，不证明最小用例数、高阶覆盖、实际系统行为或缺陷检出。

## 事务与授权

所有业务写入采用READ_COMMITTED，在共享部门行锁后刷新当前账号与角色，并手工检查整个计划版本。命令指纹包括操作者、路径语义及完整有限DTO。授权和当前范围检查先于缓存响应；重复成功命令返回稳定响应，不重复写入。删除草稿参数或禁配的重试不要求已删除实体仍存在。

批准验证当时输入和生成JSON散列，执行和报告继续校验批准摘要。报告冻结人工结果，封存校验方案与报告摘要。系统没有外部不可篡改存证，数据库管理员仍可改变数据；普通摘要不能替代可信审计制度。

单实例目录查询受限，计划最多由maxRecords控制（100至1000），成功命令最多10000，每计划生成50次；HTTP列表每页1至50。没有多租户、横向扩容、自动测试执行、发布审批或连续参数求解。
